Chapter 2 — UNamur, AMSI 2026-2027. What UML is, what it is not, and the ways it is used.

## 1. UML in a nutshell
- [[UML]] : Unified Modelling Language, OMG standard, mostly graphical, general purpose ; a **language**, not a method

## 2. UML diagrams
- [[UML Diagrams]] : structure diagrams (class, object…) vs behaviour diagrams (use case, activity, state machine, sequence…)

## 3. Usages and styles
- [[UML Usage Styles]] : problem vs solution ; sketch, blueprint, programming (Fowler)

## Strengths and limitations

| Strengths | Limitations |
|---|---|
| Standardised, widely recognised | Large language, many rarely used constructs |
| Structural **and** behavioural modelling | Semantics not equally formal for all constructs |
| Several abstraction levels | Keeping diagrams consistent needs discipline |
| Extensible (profiles, stereotypes) | Tools often support only subsets |
| Supported by many tools | |

## Review questions
- Is UML a development method? → [[UML]] (no : method = notation(s) + process + tools ; UML is only the notation)
- Who maintains UML? → [[UML]] (the Object Management Group, OMG)
- Which two families of diagrams does UML offer? → [[UML Diagrams]] (structure and behaviour)
- What are Fowler's three usage styles? → [[UML Usage Styles]] (sketch, blueprint, programming)
